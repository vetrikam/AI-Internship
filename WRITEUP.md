# Write-up

**Plan mode.** I used plan mode for the team configuration design, because the decisions affect the whole monorepo. Project conventions belong in the shared `CLAUDE.md`, while my personal rule stays in `~/.claude/CLAUDE.md`, and the test rule has to match the test naming used across the repo. Planning let me check the file names first. The starter mixes `test_*.py` files with `tests/` folders, so the rule glob covers both rather than the `*.test.*` pattern from the generic guide.

**Direct.** I added `.mcp.json` directly, without a plan. It is a single file with one server and a fixed format. The only decision was to reference the token as `${GITHUB_TOKEN}` rather than storing it. I confirmed it worked by opening `/mcp`, which showed the github server as Connected, and by checking that no `ghp_` string was committed with `git grep`.

**Skill rather than CLAUDE.md.** I put the codebase analysis in a skill, not in `CLAUDE.md`. `CLAUDE.md` loads into every session, so it should hold standards that apply to all work. The analysis runs occasionally, reads many files across eight bootcamp folders, and produces long output. I set `context: fork` so that exploration stays out of the main conversation and only the summary returns. Running `/codebase-analysis tests` showed that only one of the five test files is a real pytest suite. The other four are manual scripts that need a live server or API, and none follows the test rule I wrote. That is the next thing to fix.
